# Руководство по редактированию контента — Buy & Bring Solutions

Это руководство объясняет простыми словами, **где и как менять тексты, контакты,
статистику, услуги, кейсы, изображения и SEO** на сайте, как добавить шестой язык
и как протестировать проект перед публикацией. Программировать для этого не нужно —
почти всё хранится в отдельных файлах с данными.

> Технологии: Next.js 16 (App Router) + React + TypeScript. Локали: `pl`
> (основная), `uk`, `ru`, `de`, `zh`. URL-адреса имеют префикс языка, например
> `/pl/uslugi`, `/de/uslugi`.

---

## 1. Где менять номера телефонов и WhatsApp

Файл: **`src/config/contacts.ts`**

- Объект `phones` содержит три региона: `pl` (Польша), `ua` (Украина), `cn` (Китай).
- Для каждого номера меняйте:
  - `display` — как номер показывается на сайте;
  - `tel` — номер для ссылки «позвонить» (только `+` и цифры);
  - `whatsapp` — ссылка WhatsApp (или `null`, если нет);
  - `telegram` — ссылка Telegram (или `null`, если официальной ссылки нет).
- Какой номер показывается как основной для каждого языка — задаётся в
  `localePrimaryRegion` (PL и DE → польский, UK и RU → украинский, ZH → китайский).

## 2. Где менять email

Файл: **`src/config/contacts.ts`**, переменная `contactEmail`.
Email одинаковый для всех языков.

## 3. Где менять адреса

Файл: **`src/config/contacts.ts`**, массив `addresses` (Украина и Китай).
Польский/варшавский офис **намеренно не указан** — добавьте его только когда
появится подтверждённый адрес.

## 4. Где менять статистику компании

Файл: **`src/config/company.ts`**, объект `companyStatValues`:

- `experience` — годы опыта (сейчас `17`);
- `clients` — число клиентов (сейчас `275+`);
- `containers` — число контейнеров (сейчас `110+`).

Эти значения используются в нескольких местах. **Не добавляйте непроверенные
цифры** (отзывы, рейтинги, число отправок в месяц и т. п.). Текстовые подписи к
статистике для каждого языка лежат в файлах переводов (`stats` в
`src/i18n/messages/*.json`).

## 5. Где менять название бренда и логотип

- Название, короткая форма, дескриптор: **`src/config/company.ts`**.
- Логотип сейчас — текстовый блок `B&B` в **`src/components/layout/BrandLogo.tsx`**.
  Чтобы поставить официальный логотип: положите файл в `public/brand/`
  (например `public/brand/logo.svg`) и замените в `BrandLogo.tsx` блок на `<Image>`.

## 6. Где добавить или изменить услугу

Файл: **`src/content/services.ts`** — массив `serviceModules` (структура: id, иконка,
этап, slug). Тексты услуг (заголовок/описание) сейчас на польском в этом же файле
(мастер-копия). У четырёх услуг есть отдельные страницы — их содержимое лежит в
`src/content/pages/uslugi-*.ts`.

## 7. Где добавить кейс (реализацию)

Файл: **`src/content/case-studies.ts`** — массив `caseStudies`. У каждого кейса:
`id`, `slug`, `title`, `categoryId`, `summary`, `coverImage`, `challenge`, `scope`,
`outcome`, `gallery`. Необязательные поля (`destinationCountry`, `publishedAt`,
`status`) **скрываются автоматически**, если пустые — не выдумывайте страну/дату.
Категории — массив `caseStudyCategories` в том же файле.

## 8. Где менять тексты главной страницы

- **Hero, статистика, блок доверия, заголовки секций** — в файлах переводов
  `src/i18n/messages/*.json` (разделы `hero`, `stats`, `trust`, `sections`).
- Структура секций главной страницы: `src/app/[locale]/page.tsx`.
- Блок «Действуем в Китае» (внизу): `src/content/about-grid.ts`.
- Категории продуктов/отраслей: `src/content/industries.ts`.

## 9. Где хранятся переводы

Папка: **`src/i18n/messages/`** — по одному JSON-файлу на язык:
`pl.json`, `uk.json`, `ru.json`, `de.json`, `zh.json`.

- `pl.json` — **мастер-копия**. Если какого-то ключа нет в другом языке, сайт
  автоматически показывает польский вариант (так ничего не «ломается»).
- Меняйте значения, **не меняя названия ключей** (например `nav.kontakt`).

> Примечание: часть длинных текстов на внутренних страницах (полные описания услуг,
> детали кейсов, разделы «О нас» и «Китай», категории отраслей) пока хранится на
> польском в файлах `src/content/*`. Для полного перевода этих блоков перенесите
> тексты в `src/i18n/messages/*.json` или переведите прямо в файлах контента.

## 10. Где хранятся изображения

Папка **`public/`**. Рекомендуемая структура:

```
public/
  brand/        — логотип, og-image (картинка для соцсетей)
  team/         — фото сотрудников (для блока контактного лица)
  china-office/ — фото офиса/работы в Китае
  services/     — фото к услугам
  industries/   — фото к отраслям
  cases/        — фото к кейсам
```

Пути к изображениям прописаны прямо в файлах контента (`image`, `coverImage`,
`gallery`, `photo`). Каждому изображению задавайте осмысленный `alt`.

## 11. Где хранятся SEO-заголовки и описания

Файлы переводов `src/i18n/messages/*.json`, раздел **`seo`** — по объекту на
страницу (`home`, `uslugi`, `proces`, `realizacje`, `oNas`, `chiny`, `kalkulator`,
`konsultacja`, `kontakt`).

Технические настройки SEO:
- адрес сайта — переменная окружения `NEXT_PUBLIC_SITE_URL` (см. раздел 14) или
  `src/config/seo.ts`;
- карта сайта — `src/app/sitemap.ts`;
- `robots.txt` — `src/app/robots.ts`;
- `hreflang`, canonical, Open Graph — `src/app/[locale]/layout.tsx`;
- структурированные данные (Organization, ContactPoint) —
  `src/components/seo/OrganizationJsonLd.tsx`.

## 12. Контактное лицо (необязательный блок)

Файл: **`src/config/team.ts`**. Пока массив `contactPeople` **пустой**, и блок
контактного лица не отображается. Чтобы активировать (например, для
Кирилла Подольского) — добавьте проверенную запись с реальными данными
(имя, должность, фото в `public/team/`, телефон, email, языки). Блок появится
автоматически на странице «Контакты». Не выдумывайте данные.

## 13. Как добавить шестой язык (например, английский)

1. В **`src/i18n/config.ts`** добавьте код языка в массив `locales`
   (например `"en"`), и при необходимости в `publicLocales`, `localeNames`,
   `htmlLang`, `hreflang`.
2. Создайте файл переводов `src/i18n/messages/en.json` (можно скопировать
   `pl.json` и перевести значения).
3. Добавьте загрузчик в **`src/i18n/dictionaries.ts`** (объект `loaders`).
4. Готово — маршруты `/en/...`, переключатель языка и карта сайта подхватят язык
   автоматически.

> Чтобы язык существовал «технически», но **не показывался** в переключателе —
> добавьте его в `locales`, но не в `publicLocales`.

## 14. Переменные окружения

- `NEXT_PUBLIC_SITE_URL` — адрес продакшен-сайта (для canonical, sitemap, OG).
- `NEXT_PUBLIC_FORM_ENDPOINT` — URL бэкенда для приёма заявок из форм.
  **Пока он не задан, формы не отправляют данные на сервер** (показывают «успех»,
  но в консоль выводится предупреждение). Укажите реальный endpoint, чтобы
  заявки доходили. Секреты задавайте в настройках хостинга (Vercel), а не в коде.

## 15. Юридические тексты

Файлы-заглушки: `src/app/[locale]/polityka-prywatnosci/`,
`polityka-cookies/`, `regulamin/`. Сейчас там текст «документ в подготовке».

Юридические данные компании (название юр. лица, рег. номер, VAT) — в
**`src/config/company.ts`**, объект `legal`. **Пустые поля не показываются** на
сайте. ⚠️ **Тексты политик и юридические данные требуют проверки юристом** перед
публикацией.

## 16. Как протестировать проект перед публикацией

В терминале в папке проекта:

```bash
npm install        # один раз, установка зависимостей
npm run dev        # локальный запуск: http://localhost:3000
npm run lint       # проверка кода
npx tsc --noEmit   # проверка типов TypeScript
npm run build      # продакшен-сборка (должна завершаться без ошибок)
```

Проверьте вручную: все 5 языков (`/pl`, `/uk`, `/ru`, `/de`, `/zh`), переключатель
языка, мобильное меню, формы, калькулятор и ссылки.

## Как откатить версию на GitHub (если новая версия не понравится)

Изменения находятся в отдельной ветке и отдельном Pull Request, поэтому
**основная версия сайта не затрагивается, пока вы не вольёте (merge) PR**.

### Вариант A — просто не принимать изменения (самый безопасный)

Не нажимайте «Merge» в Pull Request. Старая версия остаётся текущей.
Можно закрыть PR (Close pull request) — ничего в основной ветке не изменится.

### Вариант B — откат уже влитого PR через GitHub (рекомендуется)

1. Откройте влитый Pull Request на GitHub.
2. Внизу нажмите кнопку **«Revert»**.
3. GitHub создаст новый PR, который отменяет все изменения. Влейте его —
   сайт вернётся к прежнему виду. История сохраняется, ничего не теряется.

### Вариант C — откат через интерфейс коммитов

1. На GitHub откройте список коммитов (вкладка **Commits**).
2. Найдите последний коммит **до** ребрендинга и скопируйте его хэш.
3. Локально:
   ```bash
   git revert <хэш_первого_нового_коммита>..HEAD
   git push
   ```
   (или попросите разработчика). Это создаёт отменяющие коммиты, не стирая историю.

### Вариант D — вернуться к конкретной прежней версии локально (для разработчика)

```bash
git checkout main
git pull
git reset --hard <хэш_старого_коммита>   # ⚠️ удаляет более новые коммиты локально
git push --force                          # ⚠️ перезаписывает историю — делать осторожно
```

> Рекомендуется **Вариант A или B**: они безопасны и не переписывают историю.
> Вариант D используйте только если точно понимаете последствия.

### Откат деплоя на Vercel (мгновенно)

Если сайт развёрнут на Vercel: откройте проект → вкладка **Deployments** →
найдите предыдущий удачный деплой → меню «…» → **Promote to Production**
(или **Rollback**). Сайт мгновенно вернётся к прежней версии, без изменений в Git.
